# 古建保护成果工作台视觉方案

## 使用场景

界面服务于长时间桌面作业。项目负责人需要快速切换项目，专业人员需要核对对象、证据和问题，复核人员需要判断成果是否可交付。界面不模拟正式签发，也不把演示数据显示为真实模型结果。

## 结构

- 项目页：左侧分类和搜索，右侧项目列表、导入与新建操作。
- 工作区：顶部项目身份，左侧阶段导航，中部任务内容，右侧可收起助手。
- 关系条：固定使用“证据或输入—产生方式—人工核对—成果版本”四段关系，帮助追溯选中对象。
- 人工入口：任务范围确认、异常处理、代理交付确认。技术检查不要求逐项确认。

## 视觉规则

| 项目 | 规则 |
|---|---|
| 背景 | `#f5f6f8`，工作面板使用白色 |
| 文字 | 主文字 `#101828`，说明文字 `#667085` |
| 边框 | `#e4e7ec`，1 px |
| 主操作 | `#2563eb`，仅用于当前选择和主要按钮 |
| 状态 | 成功 `#067647`，警告 `#b54708`，阻断 `#b42318` |
| 圆角 | 面板 10 px，控件 7 px，状态标签可使用全圆角 |
| 字体 | Noto Sans SC、Microsoft YaHei、Segoe UI；尺寸和哈希使用等宽字体 |
| 密度 | 顶栏 56 px，侧栏条目 36–40 px，表格行 44 px |

## 参考取舍

参考 `D:\Downloads\integrations-page.zip` 的侧栏、搜索、卡片、灰白层级和紧凑控件。业务布局按古建成果流程重组，不复制其集成市场内容，也不引入 Next.js 或相同组件代码。

## 自检

- 主操作数量受控，页面不会同时出现多个同等级蓝色按钮。
- 成果状态、来源类型和正式资格分别显示，避免一个标签承担多种含义。
- 项目名称、资料名称和说明只作为文本渲染，不进入 HTML、远程链接或图片地址。
- 1280 px 保持三栏可用；较窄窗口优先收起助手，不压缩主工作区。
- 所有按钮保留键盘焦点样式，图标按钮提供可读标签。
