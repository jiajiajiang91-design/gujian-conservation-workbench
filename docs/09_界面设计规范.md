# 古建测绘工作台界面设计规范

本规范只约束界面、交互反馈和用户文案，不改变业务步骤、数据结构与处理逻辑。

参考：

- [Neubrutalism 设计指南](https://neubrutalism.com/)
- [neubrutalism.com 源码](https://github.com/neubrutalism/neubrutalism.com)

## 视觉基础

| 用途 | 规范 |
| --- | --- |
| 页面底色 | `#FFFDF5` |
| 正文与结构线 | `#000000` |
| 主操作 | `#FFD23F` |
| 当前步骤、信息提示 | `#74B9FF` |
| 已完成 | `#68C77A` |
| 待确认 | `#F2A33A` |
| 错误或不可交付 | `#EE5D5D` |
| AI 识别 | `#B8A9FA` |
| 主边框 | `3px solid #000` |
| 次级边框 | `2px solid #000` |
| 小阴影 | `3px 3px 0 #000` |
| 常规阴影 | `5px 5px 0 #000` |
| 圆角与渐变 | 不使用 |

正文保持常规字号和行距，粗体主要用于页面标题、卡片标题和关键操作。颜色必须同时配合文字、边框或图标表达状态，不能只靠颜色区分。

## 页面结构

1. 左侧显示项目、工作步骤和待办。
2. 中间左侧放需要核对或填写的内容，中间右侧放任务书、照片或图纸。
3. 右侧 AI 助手只显示结果、风险、需要确认的问题和下一步。
4. 每个步骤底部保留明确的主操作，用户不必依赖对话推进流程。
5. 窄屏时 AI 助手移到页面底部，工作步骤和主工作区不隐藏。
6. 资料区支持左右排列、上下排列和关闭；AI 助手支持收起与打开。用户的布局选择在刷新后保留。

## 控件规则

- 主按钮使用黄色底、黑色粗边和硬阴影；按下时去掉阴影并向右下移动。
- 次按钮使用白底；危险操作使用红色文字或浅红底，并写清后果。
- 输入框、下拉框、卡片和弹层统一使用直角和黑色边框。
- 表格表头使用黑底白字；当前行使用浅蓝底；待确认行使用浅橙底。
- 对话中的建议必须逐条确认后才能写入项目资料。
- 键盘焦点使用蓝色外框；减少动态效果设置开启时停用非必要动画。

## 用户文案

- 使用古建测绘人员熟悉的任务名称，例如“确认实测尺寸”“核对建筑构件”“生成并检查图纸”。
- 日常页面不显示 `token`、调用次数、模型推理、参数化脚本等研发信息。
- 不展示隐藏推理原文。等待 AI 返回时，显示由真实请求和流式响应触发的处理记录，包括请求提交、收到分析信号、开始返回回答和接收完成。
- AI 读取照片或文档得到的内容统一标为“AI 识别”；固定规则得出的结果标为“自动核对”；预置演示内容标为“示例资料”。
- 风险提示写清具体原因和后果，例如“缺少实测尺寸时不能导出正式成果”。
- 按钮使用动作和结果命名，例如“要求无误，核对资料”，避免“继续”“确定”等含义不清的文字。
