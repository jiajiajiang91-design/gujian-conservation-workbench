# 古建保护成果工作台

古建保护成果工作台是一套面向古建测绘与文保勘察团队的成果生产工具。它将单栋建筑的任务要求、照片、实测记录和历史图纸组织为可追溯的建筑数据，并生成三维模型、图纸和代理交付包。

产品聚焦现场采集之后、档案接收之前的成果生产环节。同一份建筑数据贯穿资料整理、构件记录、几何建模、制图、检查和交付。系统据此减少重复录入，并保留数据来源、版本和责任记录。

## 产品目标

v1.0 的第一验收目标是跑通一栋建筑从任务要求到代理交付包的完整链路。每个环节都要形成可公开展示的真实产出。

| 阶段 | 目标 | 验收方式 | 当前状态 |
|---|---|---|---|
| 展示阶段 | 完整链路可运行、可复现、可公开展示 | 三个演示项目从任务卡走到交付包，全部环节有内容 | 完整链路与公开仓库已完成，v1.0 功能补齐进行中 |
| 试点阶段 | 验证效率与商业价值 | 使用同一任务、资料和角色配置，对比人工流程与产品流程 | 未开始，人工基线尚未取得 |
| 正式交付阶段 | 支持真实身份、权限、签名和正式发布 | 私有部署下完成专业审核、验签和正式资格判定 | 未开始 |

试点阶段有三项目标：重复录入与逐项确认次数减少 80% 以上，单栋代理成果交付周期缩短 50% 以上，关键数据追溯完整率达到 100%。

前两项仍待验证，需要通过真实项目对照取得基线。详细口径见[核心 PRD 第 2.5 节](文档/01_产品/01_核心PRD.md#25-目标与价值)。

## 用户范围与使用场景

第一用户是承担古建测绘、文保勘察和成果生产的团队，v1.0 通过一套本地工作台服务操作人员与专业责任人。

| 角色 | 主要任务 | v1.0 中的使用方式 |
|---|---|---|
| 操作用户 | 整理资料、核对构件、修正记录、生成成果 | 直接操作工作台 |
| 责任用户 | 补充专业判断、审核成组成果、承担签发责任 | 在责任节点处理待办；本地模式只能完成代理审核 |
| 档案接收方 | 核验文件、来源、限制条件并提出退回意见 | 通过交付包参与，当前不提供独立界面 |

典型场景从一项单栋古建测绘或勘察任务开始。用户批量导入任务书、照片、实测记录和历史图纸。系统整理资料关系、建立建筑数据并生成模型与图纸。

证据不足或需要专业判断时，系统向责任人提交待办。责任人审核成果后，系统生成含来源说明、检查记录和限制条件的代理交付包。

完整主线与异常分支见[用户旅程](文档/01_产品/02_用户旅程.md)。

## 要解决的问题

产品解决成果生产过程中资料分散、重复录入、依据难以追溯和成果难以复用四类问题。

- 一栋建筑的照片、实测记录、历史图纸和任务文件分散在不同载体，资料关系依赖人工记忆。
- 同一事实需要重复写入模型、图纸、表格和交付说明，修改后容易出现版本差异。
- 实测事实、系统推测和人工决定经常缺少明确区分，成果退回时难以定位依据与影响范围。
- 一次性交付的静态文件缺少来源和版本关系，后续查询、修正与更新成本较高。

产品将资料、建筑事实、成果和责任记录放进同一条生产链，使用户可以从任一数据或图面元素返回原始依据。

## 业务流程

完整流程由五个连续模块组成，系统自动推进可确定的工作，只在责任节点等待人工处理。

| 模块 | 主要工作 | 产出 |
|---|---|---|
| M1 建档准备 | 确认任务要求，批量导入并整理原始资料 | 任务卡、资料清单、项目档案 |
| M2 建筑数据构建 | 建立建筑对象、尺寸、关系、现状与几何版本 | 建筑数据、构件清单、三维模型 |
| M3 问题处置 | 识别证据缺口、规则冲突和专业存疑，形成处理方案 | 补测清单、问题分组、人工决定 |
| M4 成果生产 | 设置图纸规则，生成平立剖与详图，执行数据和文件检查 | 图纸、检查记录、审核结果 |
| M5 交付归档 | 汇总成果、来源、限制条件与版本，支持导出和局部退回 | 代理交付包、接收与退回记录 |

资料不足时，系统保留未知状态或生成补测清单。用户选择继续时，系统可以生成带来源和限制说明的代理成果，正式资格保持锁定。

## 关键业务规则

业务规则保证建筑数据、生成成果和责任记录始终可核对。

1. **一栋建筑一份档案。** 任务要求、原始资料、建筑数据、成果与交付记录使用同一项目版本链。
2. **数据来源分别记录。** 实测事实、AI 候选、规则推算、人工决定和演示资料使用不同来源标记。推算值与估算值持续保留其来源性质。
3. **缺失事实保持未知。** AI 和程序不能补造现场实测。缺少必要证据时，系统生成补测事项或降低成果资格。
4. **同一数据驱动全部成果。** 三维模型、图纸、检查和交付包引用固定的建筑数据与几何版本。数据变化后，系统只使受影响的成果失效。
5. **AI、程序和人工职责分开。** AI 负责理解资料、分析问题和生成候选；确定性程序负责计算、几何、制图、检查和文件生成；专业人员负责补充现场事实、选择非唯一方案和审核成组成果。
6. **资格由系统计算。** 人工不能绕过证据、检查、身份和签名条件提升成果资格。本地模式固定输出代理成果。

人工节点和自动执行条件见[核心 PRD 附录 A](文档/01_产品/01_核心PRD.md#附录-a--ai-与人工节点审查)。

## 工作台体验

界面采用面向桌面专业作业的三栏工作台，视觉基调是信息密度高、状态可区分、长时间使用不疲劳。

- 左栏显示项目、任务阶段、待办和当前停留位置。
- 中栏显示当前工作对象，数据与原始证据双向联动。
- 右栏常驻一个 AI 助手，承载自然语言指令、文件导入、处理进度和责任提示。
- 用户可以在照片上框选位置并用一句话修正构件或记录。
- 系统自动完成资料分类、唯一规则计算、成果生成和技术检查。
- 证据不足、专业结论不唯一或需要成果审核时，相关分支暂停，其余工作继续。
- 来源和状态同时使用文字与形状表达，避免只依赖颜色传达信息。

界面结构见[界面与交互形态](文档/01_产品/03_界面与交互形态.md)，视觉规则见[界面视觉规范](文档/02_技术/02_界面视觉规范.md)。

## 产品范围

v1.0 限定为本地单机、单栋建筑的代理成果生产工作台，覆盖资料入库、建筑数据、问题处置、模型与图纸生成、检查、交付和项目包回导。

v1.0 定义范围包含：

- 任务要求提取与资料批量入库。
- 建筑对象、实测、现状、构件和来源关系记录。
- 规则核对、形制推算、三维模型与图纸生成。
- 问题分组、照片框选修正、成组审核与自动检查。
- 代理交付包生成、项目导入导出和局部重做。
- 通过受控动作操作工作台的 AI 助手。

当前范围排除：

- 法定签发与真实工程交付。
- 多人实时协作和跨机构数据交换平台。
- 代替现场测量或补造缺失的实测事实。
- 通用建筑设计、结构计算和施工图设计。
- 多期复查、变化监测与档案管理方独立界面。

全部 18 项功能及验收标准见[核心 PRD 第 4.3 节](文档/01_产品/01_核心PRD.md#43-功能清单)。

## 部署环境与技术结构

当前实现采用单机优先的模块化结构，浏览器本地数据库是项目数据真源，Node 服务负责模型任务和制图作业。

| 层级 | 当前实现 | 责任 |
|---|---|---|
| 工作台 | React、TypeScript、Vite | 项目、证据、模型、图纸、问题和交付操作 |
| 应用与领域 | TypeScript 模块 | 命令、版本、来源、资格、依赖和失效规则 |
| 模型与作业服务 | 独立 Node 服务 | AI 任务、受控动作、运行记录和用量 |
| 几何与制图 | Python 3.12、CadQuery 2.8 | 几何、投影、DXF、SVG 和 PDF 生成 |
| 本地存储 | IndexedDB v3 | 项目记录、资源、版本和审计 |

本地模式仅允许代理交付。后续私有部署将项目真源迁移到 PostgreSQL 与对象存储，并接入服务端身份、权限和签名。两种模式共用领域契约，同一部署只保留一个项目写入权威。

详细设计见[技术架构](文档/02_技术/01_技术架构.md)。

## 本地运行

当前工作台需要 Node 20.19 以上和 pnpm 11.16，模型识别与几何制图按需配置。

安装依赖并启动工作台：

```powershell
corepack pnpm install
corepack pnpm dev
```

工作台地址为 `http://127.0.0.1:5173`，本地服务地址为 `http://127.0.0.1:8787`。

如需使用几何与制图功能，先准备 Python 3.12 环境：

```powershell
python -m venv workers\cad\.venv
workers\cad\.venv\Scripts\python.exe -m pip install `
  --require-hashes -r workers\cad\requirements.lock
```

如需使用模型理解与识别功能，在 `apps/server/.env` 中配置 `KIMI_API_KEY`。配置项见 [`apps/server/.env.example`](apps/server/.env.example)。

缺少密钥时，确定性流程和本地数据功能仍可使用。

运行完整代码检查：

```powershell
corepack pnpm run install:legacy
corepack pnpm check
```

## 验证边界

当前成果证明完整链路可以运行和公开展示，专业资格、真实项目效率与付费意愿仍需后续验证。

- 全部图纸、模型和交付包属于代理成果，不能替代专业责任人的真实项目审核与签发。
- 高都项目缺少现场实测记录，尺寸来自形制规则与照片参照，精度受形制判断和参照条件限制。
- Dai Loy 项目的尺寸来自 HABS 图纸转录，来源标记为公开实测资料转录。
- 重复录入减少 80% 和周期缩短 50% 尚无人工对照基线。
- 乙方付费意愿属于未验证假设。验证方式是一家乙方使用同一任务与资料完成真实项目对照，并记录使用意愿、采购条件和可接受价格。
