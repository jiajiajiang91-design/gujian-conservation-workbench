# 古建保护成果工作台

把古建保护项目的一次现场记录，变成一套能追到出处的测绘成果。

资料进来，尺寸和构件被识别出来，人逐条确认，系统据此建三维模型、出平立剖图纸、做检查、打交付包。每一个数字都能点回它的来源：哪张照片、哪次实测、谁在什么时候确认的。

**这是作品集项目，不是可用于实际工程的软件。** 产出的图纸与模型标记为代理成果、未签发、未达专业样板等级，不构成专业结论。

## 它想解决什么

古建测绘的成果里，实测值、推算值和形制经验值混在一起，图纸交出去以后没人说得清哪个数是量的、哪个是推的。这套工具把这三种来源在数据结构里分开，并且让分开这件事贯穿到图面和交付包。

因此有两条硬规则：

- 不合格的尺寸进不了正式成果，系统宁可阻断也不补默认值。
- 推算值永远显示为推算值。规则给出的应然值不能当实测依据。

## 现在能做到什么

三个演示项目在首次打开时自动装载，每个都走完七步：任务卡、资料清单、实测基准、构件清单、三维模型、图纸与检查、交付包。

| 演示项目 | 资料 | 构件 | 说明 |
|---|---|---|---|
| 团队构造样板 | 2 份 | 1258 个 | 局部构造样板，验证几何与制图管线 |
| Dai Loy 赌馆博物馆 | 7 份 | 75 个 | 美国 HABS 公开实测图，验证完整工程流程 |
| 高都玉皇庙主殿 | 3 份 | 1131 个 | 中国官式木构，资料不全，用于验证阻断路径 |

助手层有 14 个受控动作，从切换视图到生成图纸到在照片上框选修正构件。动作的实现状态由代码登记表派生，测试守着，文档不能单方面宣称已交付。

## 跑起来

需要 Node 20.19 以上、pnpm 11.16（仓库用 corepack 锁定），CAD worker 用 Python 3.12 与 CadQuery 2.8，依赖与哈希锁在 `workers/cad/requirements.lock`。

```bash
corepack pnpm install
corepack pnpm check
```

启动开发环境：

```bash
corepack pnpm dev
```

工作台在 `http://127.0.0.1:5173`，服务端在 `8787`。模型识别功能需要在 `apps/server/.env` 配置 API key，配置项见 `apps/server/.env.example`；不配置时其余功能照常，识别相关按钮显示为不可用。

## 边界

- 演示数据标为示例来源，不能作为真实成果。
- 高都项目故意资料不全，用于验证系统在依据不足时会阻断而不是补齐。
- 模型识别的结果先进候选区，人工确认后才写入项目。
- 未实现按图纸自动出具专业结论，也不替代真实项目负责人的审核签发。
