# PRD 对标清单

基于 `07_PRD_MVP图纸闭环.md` v1.2（含闭环测试修订）与 [PRD模板](PRD模板.md) 提取。新 PRD 交付前、既有 PRD 重大修订后逐项检查。

**适用条件**：标注（有界面）的项仅适用于含用户界面的功能点，纯算法 / 数据 / 规范类 PRD 跳过；标注（迭代）的项仅适用于第二版及以后的迭代 PRD。

## 结构完整性

- [ ] §1 产品概述：一句话描述（不超过 50 字）、产品目标（指标加目标值加时限）、核心假设（每条配验证方式）、不做清单（每项附理由和计划阶段）
- [ ] §2 用户分析：目标用户表（角色、频率、核心任务、优先级）、用户旅程核心流程（Mermaid 流程图加步骤文字版）
- [ ] §3 需求清单：优先级定义、需求总览表（编号、名称、模块、优先级、依赖、对应场景），按用户旅程顺序排列
- [ ] §4 功能详细说明：每个 P0/P1 需求一条，九要素齐全（需求编号、优先级、用户故事、前置条件、主流程、分支流程、界面要求（有界面）、数据要求、验收标准）
- [ ] 验收标准每条可独立验证，有明确的通过与不通过判据，量化处给阈值
- [ ] §5 非功能性需求、§6 数据埋点与指标：按需填写，不为凑全而填
- [ ] §7 术语表：假设读者不了解行业用语
- [ ] （迭代）版本变更点相对上一版可定位：改了哪些功能点、为什么改

## 命名一致性

- [ ] 同一功能点在需求总览（§3）、功能详细说明标题（§4）、用户旅程（§2.2）、原型屏引用中的名称一字不差
- [ ] 功能点名遵循 对象加动作加状态 三元结构，无时序词、无虚动词
- [ ] 流程名遵循 条件加对象加动作 结构
- [ ] 页面名取原型上最醒目的文字，PRD 内引用与原型屏一字不差（有界面）
- [ ] 原型屏编号连续、无缺口；预留屏除外，预留必须放在所属功能点末尾（有界面）
- [ ] 新概念用中文编号加短名；引用既有编号（R001 到 R006、H1 到 H4、P0/P1/P2）保留原编号并在首次出现处附中文说明

## 流程与状态质量

- [ ] 每个功能点覆盖正常态加至少一个异常态，分支流程不为空
- [ ] 有加载或等待态的流程必须有成功态和失败态（有界面）
- [ ] 每页出口穷举、无死路；仅有重试出口而重试可能永久失败的页面必须有第二出口（有界面）
- [ ] 同一底层操作未被拆成两个流程；被多条用户路径共用的页面已识别标注；流程与页面不同名
- [ ] 页面文案回答"这对用户意味着什么"，不描述系统状态（有界面）
- [ ] 表单控件按是否驱动出图模板与档案统计，区分下拉词表与自由文本输入（有界面）

## 图表质量

- [ ] 流程图一律 Mermaid，禁 ASCII 图
- [ ] 图中节点名与正文内联引用一字不差
- [ ] 其余遵循 [图表使用规范](图表使用规范.md)

## 内容边界

- [ ] 结论在 PRD，证据在研报：回答"怎么得出的"的内容移出正文，只留结论与引用指针
- [ ] 无文档信息表、无修订记录、无元叙述
- [ ] 数据点均有来源标注，或标为假设并给出验证方式
