# 产品判断

## 使用顺序

按当前问题选一份，不必全读：

| 问题 | 读取 |
|---|---|
| 目标用户是谁、场景怎么走 | `references/用户与场景.md` |
| 这版做什么、什么延后 | `references/MVP与优先级.md` |
| 模型怎么选、投入是否划算 | `references/商业与模型成本.md` |
| 这份文档写得对不对 | `references/文档审阅.md` |

## 判断原则

- 业务价值落在降低成本、提高效率、扩大影响力三类之一，用可量化指标表达。三类都不命中的方向不继续。
- 功能点过多时反向合并：用更少的模块包全同样范围，各模块的描述深度一致。
- 需求不明确时逐条向用户确认，不自行猜测。
- 每个决策从四个视角自审：产品看方向与边界，外行看价值主张，开发看可实现性与依赖，用户看真实痛点是否被解决。
