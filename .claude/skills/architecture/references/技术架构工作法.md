# 技术架构工作法

## 进入条件

以下内容均已确认后才进入架构设计：

- PRD 的目标用户、核心场景和版本范围。
- 输入、输出、业务规则和人工责任。
- 功能清单、异常流程和验收标准。

缺少任一项时，技术架构师列出问题并退回产品经理，不用技术方案补产品空白。

## 分析顺序

1. **现状盘点**：读取目录、入口、数据源、调用关系、状态存储、构建方式和测试。
2. **问题定位**：区分数据耦合、模块耦合、接口缺失、状态混乱、安全风险和不可测试问题。
3. **约束确认**：记录部署环境、数据合规、性能、成本、兼容和阶段边界。
4. **方案比较**：至少比较保守改造与目标架构，说明收益、代价和迁移风险。
5. **架构定义**：明确数据、领域对象、模块、服务、接口、错误和审计记录。
6. **交叉检查**：由独立模型或审阅者检查遗漏、过度设计和迁移可行性。
7. **任务拆分**：每项任务可独立完成、验证、中断恢复和回退。

## 必须说明的架构内容

### 数据

- 项目、建筑、构件、证据、尺寸、规则、结果、责任和版本怎样关联。
- 每个字段的来源、状态、更新者、必填条件和影响范围。
- 样例数据怎样独立存储、导入、导出和替换。

### 模块

- 输入与解析。
- AI 理解与模型调用。
- 确定性规则和计算。
- 工作流编排与人工停靠。
- 工作区与交互。
- 成果生成、检查、交付和审计。

### 接口

- 模块输入、输出和错误格式。
- 模型失败、超时、降级和重试。
- 数据变更后受影响范围和重新计算方式。

### 非功能要求

- 安全与密钥管理。
- 数据隐私和访问权限。
- 性能、调用成本和使用限制。
- 日志、测试、备份和恢复。

## 架构方案输出

1. 背景、目标和约束。
2. 当前结构与主要问题。
3. 推荐方案和未选方案。
4. 分层结构、模块职责和数据契约。
5. 迁移阶段、依赖和回退方式。
6. 测试与验收方法。
7. 风险、未知项和需要确认的决定。
8. 可执行任务清单。

架构方案获得 JIAJIA 确认前保持规划状态，不修改代码。
