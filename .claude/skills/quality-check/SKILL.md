# 质量检查

## 目标

机器能判定的规则由脚本执行，不靠人逐条记。脚本报出的每一条都要处理完再收口，不留静默差异。

## 使用顺序

改完东西之后：

```
node .claude/skills/quality-check/scripts/run-all.mjs
```

单元收口或提交前，追加测试与演示矩阵：

```
node .claude/skills/quality-check/scripts/run-all.mjs --full
```

也可以单独跑其中一步：

| 脚本 | 查什么 |
|---|---|
| `check-docs.mjs` | 禁用字符、中英文空格、markdown 链接、文档里写的仓库路径、源码里写死的文档路径 |
| `check-state.mjs` | 单元三件套是否齐、验收判定进度、路线图与目录事实是否一致、索引与实际文件是否一致、pm-context 指针是否可达 |

`check-docs.mjs` 默认跳过 `文档/99_历史归档` 与 `文档/05_验证证据`，两者刻意保留当时状态的旧路径。加 `--all` 连它们一起查，加 `--verbose` 展开建议核对项。

## 结果分两级

**必须修复**：链接失效、路径不存在、源码引用的文档路径不存在、禁用字符。这类会让别人点不开、让构建或测试失败，收口前清零。

**建议核对**：中英文空格、变更对照表里的旧路径。这类按文件聚合显示，历史笔记里的存量不必回头改，新写的内容要改对。

## 检查通过之后要更新什么

脚本只报差异，不改写文档，因为状态描述是语义内容。按报出的差异更新这几处：

| 情况 | 更新位置 |
|---|---|
| 单元验收全部判定完毕 | 提请 JIAJIA 确认，确认后把单元目录整体移入 `文档/99_历史归档/05_实施单元归档/`，路线图第六节留一行 |
| 单元状态变化 | `文档/04_实施单元/00_路线图.md` 的进行中、下一步、单元一览三处 |
| 权威文档改名或新增 | `.claude/context/pm-context.md` 指针表与 `文档/00_索引.md` |
| 文档路径变动 | 源码里写死该路径的地方，`check-docs.mjs` 第 5 项会报出来 |

## 边界

脚本查的是形式，不是内容。以下要人判断，通过不等于合格：

- 每章第一句是不是结论，数据有没有标来源，假设有没有写验证方式
- 验收条件本身是否成立，而不是表格填满了
- 结论与证据是否对得上

技术检查通过不代表专业成果合格，这条口径与产品一致。
