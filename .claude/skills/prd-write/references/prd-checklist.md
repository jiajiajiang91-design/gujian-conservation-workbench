# PRD 自检清单

完稿后逐项检查，再运行 `../scripts/prd-check.ps1`。标注（产品层）的项只适用于产品层 PRD，底层模块跳过；标注（有界面）的项只适用于含界面的功能。

## 一、骨架完整性

- [ ] 四段齐全且顺序正确：文档信息、需求背景、业务流程、功能规划
- [ ] 1.1 需求摘要 2 至 3 句，说清功能、场景、价值
- [ ] 1.2 流程概览有一句话概述加流程图，核心业务 3 至 5 条
- [ ] 核心业务每条出现业务主体本身，不只写抽象动作
- [ ] （产品层）2.1 愿景一句话包含为谁、解决什么根本问题、达成什么状态
- [ ] 2.2 目标用户的特征名保持泛化，未写死在某一行业
- [ ] 2.3 现状与问题按维度分类，有"结果"和"根因"两段收尾
- [ ] 2.5 目标与价值的业务目标可量化，落在降低成本、提高效率、扩大影响力之一
- [ ] （产品层）2.6 市场竞品有研报引用、成熟度表和结论三部分
- [ ] 历史版本的需求背景在 2.7，未新开文档
- [ ] 3.2 用户故事只有"操作加价值"，无功能名与机制细节
- [ ] 4.1 版本规划写业务方向词，无功能点枚举
- [ ] 4.3 功能清单有"页面"列，未另设页面旅程表
- [ ] 省略的节连同标题一起删除，无空节

## 二、收敛度

- [ ] 模块数量已做过反向合并检查：更少的模块无法包全同样范围
- [ ] 各模块的描述深度一致，无一处过细一处过粗
- [ ] 功能清单中每条都能对应到 3.2 的某个用户故事

## 三、内容边界

- [ ] 全文无技术方案、框架选型和实现细节
- [ ] 结论在 PRD，证据在研报：回答"怎么得出的"内容移出正文，只留结论与引用
- [ ] 数据点均有来源标注，或标为假设并给出验证方式
- [ ] 验收标准每条可独立验证，量化处给阈值

## 四、命名一致性

- [ ] 同一功能点在功能清单、用户故事、流程图中的名称一字不差
- [ ] 功能点名为"对象加动作加状态"结构，无时序词与虚动词
- [ ] （有界面）页面名取界面上最醒目的文字，文档内引用一致

## 五、流程与状态

- [ ] 每个功能覆盖正常态与至少一个异常态
- [ ] 流程图中每个节点有出口，无死路
- [ ] 同一底层操作未被拆成两个流程

## 六、表达

- [ ] 每节第一句是结论
- [ ] 无黑话、空洞形容词、情感渲染词、军事武侠类词汇
- [ ] 无破折号与直角引号，中英文之间有空格，数字带单位
- [ ] 流程图为 Mermaid，classDef 三属性齐全，节点不超过 12 个
- [ ] 表格列数不超过 6
