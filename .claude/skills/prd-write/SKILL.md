# 写 PRD

## 目标

一份 PRD 输入给 AI，AI 就能产出预期结果。中间不需要补充说明。产出不符合预期时，先反查这份 PRD 哪里模糊，而不是给 AI 补步骤。

## 使用顺序

1. 读 `references/prd-template.md` 取骨架。四段固定：文档信息、需求背景、业务流程、功能规划。
2. 按 `references/doc-guidelines.md` 控制语言与结构。
3. 图表按 `references/diagram-guidelines.md`。
4. 完稿后用 `references/prd-checklist.md` 自检。
5. 运行 `scripts/prd-check.ps1` 做机器校验，问题清零才算完成。

## 边界

- PRD 只写目的、场景、价值和验收标准，不写技术方案、框架选型和实现细节。技术由架构环节承接。
- 每节开头标注适用条件。产品层 PRD 写全，底层模块省略愿景、行业趋势和市场竞品。
- 需求来源唯一：先改 PRD 再改实现，不从实现反向补文档。
- 历史版本的需求背景移入"旧版本"节，不新开文档。

## 收敛要求

模块和功能点分布过多时，反向合并：用更少的模块包全同样范围，并把各模块的描述深度拉齐。十个模块能被五个覆盖，就用五个。
