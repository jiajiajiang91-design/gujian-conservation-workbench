# 01 · 用户与场景分析


## 1. 用户分层

用户按与闭环的距离分四层。直接操作层（乙方绘图员、项目负责人）是 MVP 用户，其余三层不直接操作产品。00 §4.2 的买单方四角色视图（局长、科员、省市局、文保员）并入审核接收层至标准统计层，作为买单方内部的组织视图。

**表 1：用户分层表**

| 层 | 具体岗位 | 痛点 | 动机 | 能力边界 | 使用频率 | MVP 角色 |
|----|----------|------|------|----------|----------|:--------:|
| 直接操作层 | 乙方绘图员、内业整理员 | 描线人天高，规范细节多易返工 | 省人天、少返工 | 熟 CAD 和制图国标，营造法式术语熟悉度存疑（假设7） | 每项目高频 | P0 |
| 直接操作层 | 乙方项目负责人 | 对交付质量担责，初稿把关成本高 | 交付一次通过 | 懂规范全貌，不亲手描线 | 每项目 | P0 |
| 审核接收层 | 区县文物科员、文管所 | 一人对几百个点，迎检拿不出合规成果 | 上面检查时拿得出手 | 懂业务，多数不用 CAD | 每项目验收、每年检 | P1，交付对象 |
| 审核接收层 | 修缮方案评审专家 | 图纸质量参差 | 审得快、依据清楚 | 专业深 | 每工程 | 间接（假设8） |
| 买单决策层 | 区县文物局局长 | 怕出事、要政绩 | 看得见、讲得出、不出事 | 不接触产品 | 采购决策时 | 购买叙事对象 |
| 标准统计层 | 省市文物局 | 区县数据口径不统一 | 数据质量可控 | 不接触产品 | 汇总、督查时 | 影响者 |

规模量级：买单决策层对应全国 2844 个县级行政区（民政部区划口径，00）；直接操作层所在的文保勘察设计资质单位总数无公开汇总（00 证据 E19），规模标未知。

本期不进分层：住建口（另一套建档标准，02 MRD 定 P1）、高校科研（00 打分已排除）、业余文保员（不产生出图动作）、公众（非用户）。

已确认边界：区县科员自己用产品出简版图纸不算 MVP 用户。MVP 输入需要实测尺寸，科员通常没有外业测绘的能力和时间（假设6）；该场景作为灰度期的观察信号处理。

## 2. 使用动作

MVP 产品内动作：上传、打标、录入尺寸、校正、生成图纸、导出。分析覆盖直接操作层。

**表 2：绘图员动作对照（三段）**

| 阶段 | 动作 | 频率 | 说明 |
|------|------|------|------|
| 用之前 | 外业拍照、手测尺寸（草图或表格记录）、回所整理选片 | 每项目 | 产品不覆盖；照片质量和尺寸记录习惯决定输入可用性（假设9、假设10） |
| 用之中 | 在项目下建建筑单元、上传照片并按部位打标、录入实测尺寸表、触发识别、逐项校正部件清单、选比例生成图纸、导出 | 每立面 | 对应 07 PRD R001 到 R006；打标和录尺寸是新增动作，校正是替代动作中的信任建立点 |
| 用之后 | 在自己的 CAD 里做几何微调、并入整套交付物（平面剖面等产品外图纸）、提交负责人审核 | 每立面 | 产品输出是交付包的一部分，嵌入既有工具链而非替代它 |

**表 3：项目负责人动作对照（三段）**

| 阶段 | 动作 | 频率 |
|------|------|------|
| 用之前 | 接项目、排人天分工、定交付标准 | 每项目 |
| 用之中 | 建项目填委托方信息、审 AI 初稿与校正留痕、核对合规项、确认定稿导出 | 每项目 |
| 用之后 | 交付委托方、被退回时安排返工、复盘人天（人天对比数字即产品价值的证据） | 每项目 |

核查结论：R001 到 R006 覆盖了产品内全部动作。发现一个流程缺口：委托方退回后的返工路径未定义（尺寸改动后的版本管理、图签版本号升级规则），进 backlog 候选，不改本期 PRD。

## 3. 场景分析与需求说明

场景1（修缮勘察现状立面图）为 MVP 主场景。

### 3.1 目的分流

**表 4：用户目的分流**

| 目的 | 什么情况下发生 | 对产品的要求差异 |
|------|----------------|------------------|
| 常规交付出图 | 修缮勘察、建档测绘项目的正常流程 | 全要素，精度和合规优先 |
| 返工补图 | 委托方退回、验收不过、迎检临时补 | 时间压力最大，改动要快 |
| 估算级快图 | 初勘无完整实测、方案讨论、投标展示 | 速度优先，接受标（估） |

### 3.2 场景卡

**场景1：修缮勘察现状立面图（MVP 主场景）**

| 项 | 内容 |
|----|------|
| 触发条件 | 文保修缮工程立项后，勘察设计单位进场做现状测绘，图纸需通过方案评审 |
| 上下文压力 | 评审专家逐项看图，图纸质量直接关联方案能否通过。国保级修缮约 400 项/年，不含省市县级（00 证据 E17） |
| 参与角色 | 绘图员操作全链，负责人审核定稿 |
| 动作序列 | §2 表 2、表 3 的完整动作链 |
| 痛点 | 描线人天高（04 §2）；规范细节多，返工常见 |
| 需求 | R001 到 R006 全覆盖，精度和溯源要求最高 |
| 优先级依据 | 频率高（00 证据 E17），直接验证 H2。单个项目付费额高于建档类单栋均摊（推断，访谈核对） |

**场景2：建档测绘项目批量出图**

| 项 | 内容 |
|----|------|
| 触发条件 | 政府建档类采购项目，乙方按合同对几十到上百栋建筑测绘建档 |
| 上下文压力 | 验收焦点是合规统一（命名、图签、格式），单栋精度要求低于场景1。量大，单栋操作成本被放大 |
| 参与角色 | 同场景1 |
| 动作序列 | 同场景1，上传和出图动作高频重复 |
| 痛点 | 批量项目的格式统一靠人，返工常因合规细节不一致 |
| 需求 | R001 到 R006 覆盖单栋流程。新需求候选：批量上传与批量出图 |
| 优先级依据 | P1，进 backlog。第一批验证用单栋即可 |

**场景3：初勘估算级快图**

| 项 | 内容 |
|----|------|
| 触发条件 | 项目前期只有照片、无完整实测，需要示意级图纸做方案讨论或汇报 |
| 上下文压力 | 速度优先，精度靠标（估）声明保障 |
| 参与角色 | 绘图员单人 |
| 动作序列 | 跳过或部分跳过录入尺寸，其余同场景1 |
| 痛点 | 目前要么不画，要么徒手示意（推断，访谈核对） |
| 需求 | R002 无实测分支加 R005 的（估）标注机制（07 PRD 已有） |
| 优先级依据 | 不新增功能。是乙方首次接触产品的低门槛入口，灰度期的第一触点场景 |

## 4. 假设清单（假设5 到假设12）

假设1 到 4（H1 到 H4）见 02 MRD 表 11。验证动作以 08 验证与灰度方案表 1 为准。

**表 5：用户与场景假设清单**

| 编号 | 短名 | 假设内容 | 验证方式 | 若不成立的影响 |
|------|------|----------|----------|----------------|
| 假设5 | 乙方分工 | 项目负责人与绘图员的分工真实存在 | 乙方访谈 | 直接操作层合并为一个角色，校正与审核流程简化 |
| 假设6 | 科员自用 | 部分区县不外包，科员有自行出简版图的需求 | 区县访谈；查公开招标中小额零星项目占比 | 若成立，直接操作层增加科员分支，灰度对象改变 |
| 假设7 | 术语增值 | 绘图员熟 CAD 但不熟营造法式术语，AI 部件命名是增值点 | 乙方访谈 | 部件术语标注从卖点降为普通功能 |
| 假设8 | 评审门槛 | 修缮工程图纸须过专家评审，合规是硬门槛 | 已验证成立，升级为事实：文物保护工程管理办法规定勘察设计方案按文保单位级别报文物行政部门审批，审批时组织专家评估论证（gov.cn，2026-07-10） | 不再适用 |
| 假设9 | 照片质量 | 乙方外业常规拍摄立面照片，质量满足识别（全景加细部） | 乙方访谈，看真实项目照片 | 输入端需增加拍摄指引，采用门槛上升 |
| 假设10 | 尺寸记录 | 实测尺寸有可录入的记录（草图或表格），结构化录入负担可接受 | 乙方访谈，实测录入一个立面的耗时 | 录入交互重做，或支持拍照识别尺寸草图 |
| 假设11 | 输入成本 | 打标加录入的耗时小于省下描线时间的 20%（20% 为占位初设，访谈后修正） | MVP 对照交付时分动作计时 | 采用意愿不成立，输入流程需重新设计 |
| 假设12 | 立面占比 | 画立面图的时间占一个项目全部图纸绘制时间的比例不低于三分之一（占位初设，访谈后修正） | 乙方访谈问真实项目的图纸类型人天分布 | MVP 只做立面，若占比低则单点价值感知弱，横向扩图纸类型的优先级提前 |
