# 动作层接线验证（D4/D5/D6）

> 日期：2026-08-16
> 范围：assistant 动作层接线（提交 e085726、9acc1d7、75ddb21）与 D6 验收
> 状态：真实 Kimi K2.6 函数调用分发已验证；所有写入与作业动作走确认机制

## 1. 结论

14 个动作的目录、三级分发、确认机制和前端执行链全部接通。真实模型分发基准 44 条用例命中率 88.6%（模型直判 38、重试后命中 1、关键词 0、未中 5，全部为边界用例）。浏览器端到端验证覆盖确认允许、拒绝两分支，允许分支真实触发 CadQuery 几何作业。

## 2. 分发基准（真实 Kimi K2.6）

- 用例：`dispatch-cases.json`（14 动作各约 3 条真实表达 + 5 条边界表达，共 44 条。正式用例集由主对话按 D6 约定补充后可直接重跑）
- 报告：`dispatch-benchmark-report.json`（逐条含尝试链与命中档位）
- 运行方式：`node --env-file=apps/server/.env apps/server/dist/actions/dispatch-benchmark.js <cases> <out>`

| 档位 | 条数 |
|---|---:|
| 模型直判命中 | 38 |
| 参数重试后命中 | 1 |
| 关键词退路命中 | 0 |
| 未命中 | 5 |

未命中 5 条均为边界用例，逐条分析：

1. 这根柱子的尺寸是从哪来的 → answer_question（期望 locate_evidence）：语义可辩，回答问题并给引用也可接受。
2. 这个项目还缺哪些资料 → parse_task_brief（期望 answer_question）：模型选择更主动的动作，前置条件与逐条确认兜住风险。
3. 你觉得这个项目做得怎么样 → run_data_check：闲聊被派成只读检查，无害但列入提示词优化候选。
4. 删掉所有构件 → switch_view：危险表达未落 propose_modification，实际派发为只读视图切换，未造成写入；列入提示词优化候选（危险写请求应引导到逐条确认的修改建议）。
5. 把图纸发给王工 → export_deliverable（期望兜底回答）：转办属第 3 代占位，模型近似到导出；普通导出为直接执行档，此类误派的实际后果是多导出一个文件，列入优化候选。

发现并修复的真缺陷：executeWithTools 原发送 temperature 0.3，kimi-k2.6 仅接受 0.6，导致全部模型调用 HTTP 400 静默降级为关键词档（首轮基准命中率 50% 即此症状）。修复后按上表。该缺陷说明交付测试中的 fakeFetch 无法替代真实供应商联调。

## 3. 浏览器端到端（127.0.0.1:5173，真实服务）

项目：团队演示构造项目（跨项目泛化，886 构件）。记录方式为页面 DOM 文本抓取（原文保存于本文件与对话记录）。

| 步骤 | 结果 |
|---|---|
| 指令：生成三维模型 | 模型返回对话式追问（已有几何版本，是否覆盖），按文本透传显示 |
| 指令：确认，重新生成三维模型 | 派发 generate_geometry，弹确认卡：动作名、参数（note 含用户意图）、耗时预估、三按钮 |
| 点击拒绝 | 返回"已拒绝，该动作未执行"，确认卡关闭，令牌一次性作废 |
| 再次发起并点击允许执行一次 | 返回"已确认，执行生成三维模型"，POST /api/cad-jobs 200，真实 CadQuery 作业启动 |
| 指令：切到构件清单（前一轮无密钥状态验证） | 关键词退路派发 switch_view，工作区真实切换到对象与构件页 |

密钥挂载方式：从旧原型 .env 以变量名转换脚本写入 `apps/server/.env`（值不显示、不进 Git，.gitignore 已覆盖）。
