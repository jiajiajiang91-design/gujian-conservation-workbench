# T0b 现有改动处置与资产处置矩阵

> 本节原为技术架构 12.1，2026-08-21 移出。记录 T0b 阶段脏工作区的快照流程与 18 类资产的处置分类，已执行完毕。

## 一、快照流程

Git 标签不能保存未提交和未跟踪文件。任何分类、移动或清理之前，先建立可实际恢复的本地快照：

1. 在忽略目录（如 `recovery/<日期>-pre-<任务名>/`）保存当前分支、HEAD、Git 状态和工具版本。
2. 分别保存工作区与暂存区的 binary patch，确保已跟踪文本和二进制改动都可恢复。
3. 将未跟踪的源码、合同、测试、报告和二进制按原相对路径归档。归档前执行密钥和隐私扫描。
4. `.env` 不进入普通归档；只记录路径、字节数和哈希，内容由用户控制的密钥存储单独备份。
5. 为 patch、归档和每个源文件建立 SHA-256 清单，并记录未跟踪目录的包含与排除规则。
6. 在临时 worktree 中从当前 HEAD 恢复 patch 和未跟踪归档，比较 Git 状态、文件清单和 SHA-256。
7. 恢复验证通过并保存报告后，才允许分类、提交或排除现有改动。恢复标签只能标记随后形成的已提交节点，不能代替该快照。

|------|------|----------|------------------|

| v2 DXF、SVG、PDF 跨格式生成器 | 修正后迁移 | 原生 CAD 对象和多格式输出已经过技术测试 | 只复用通用代码；重新生成、检查和专业审核 |

| v3 数据合同、稳定 ID 和接口模型 | 修正后迁移 | 中性构件语义、对象映射和接口图可复用 | 修正单位类型、未知项和资格字段；补迁移测试 |
| v3 生成器和独立验证器 | 修正后迁移 | 稳定 ID、几何原语、面片接口、攻击测试和确定性检查可复用 | 先保全 demo；再移除 2×2 柱、瓦列/行、椽和门窗数量硬编码及验证器复制计数 |
| v3 旧 `geometry/` 与失配 prefreeze 报告 | 失败或历史证据保留 | 可以还原 881/24 与 886/2118 两套结果的差异 | 标记 `superseded` 或 `invalidated`；不能混入当前构建 |
| 根领域和应用契约 | 修正后迁移 | 项目、事实、命令和来源基础可复用 | 与 PRD v2.2、v3 schema、事务和迁移测试一致 |
| `packages/infrastructure` 配置 | 修正后迁移 | 包边界可以保留 | 当前只有配置，必须与仓库源码、事务测试、失败恢复和根锁文件一起提交 |
| 旧 React 入口、固定 fixture、固定 UUID 和假助手 | 失败或历史证据保留后淘汰 | 可锁定旧行为、固定项目反例和假成功缺陷 | 旧入口不扩展；迁移测试覆盖后退出新运行路径 |
| 旧 `ProjectPackageService`、ZIP reader 和 IndexedDB repository | 修正后迁移 | 项目包校验、两阶段导入和 v2 存储经验可复用 | 去除固定项目分支，适配 v3 契约并保留现有测试 |
| 旧 `ProjectCommandService`、Artifact/Delivery 和 provenance | 修正后迁移 | 命令幂等、代理成果和来源关系基础可复用 | 统一唯一写入口、精确版本查询和资格分离后迁移 |
| 旧通用 UI 组件及其测试 | 修正后迁移 | 搜索、导航、表格、面板和可访问性基础可复用 | 去除项目文案、固定 UUID 和假助手依赖；保留组件测试 |
| 旧工作台 30 项现有测试 | 直接保留 | 可锁定旧行为和迁移反例 | 测试口径标明“旧行为”，不得用来证明新架构完成 |
| 根 `package.json`、`tsconfig.json` 的未提交改动 | 修正后迁移 | 可支持新 workspace | 与新应用脚手架、可安装依赖、锁文件和测试一起提交，不单独提交半成品 |
| staging、缓存和 `__pycache__` | 淘汰 | 无业务或验证价值 | 记录忽略规则后不进入 Git |
| `.env`、外部 DWG、商业软件配置 | 淘汰 | 只能在本地人工参照或运行 | 禁止进入 Git、项目包和生成依赖 |

分类为“修正后迁移”的资产采用最小改动并保留原测试；分类为“失败或历史证据保留”的资产保留失败原因、绑定版本和哈希，不进入当前运行路径。表中的“淘汰”只表示退出目标运行路径、Git 跟踪或生成依赖，不授权删除用户原文件；删除本地外部参照或历史资产需要单独确认。删除状态的 AutoCAD、QCAD 证据必须先记录绑定的旧 DXF 文件哈希、来源提交、失效原因和替代报告。每个处置任务先记录文件清单和 SHA-256，有效源码与测试进入对应任务提交，可重复生成的大文件按 §12.4 处理。
