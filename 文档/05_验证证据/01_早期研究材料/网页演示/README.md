# 古建档案引擎 · 图纸闭环 Demo

可点击操作的软件 demo，对应 10 低保真原型的主流程。纯静态页面，无后端，无构建工具，双击 `index.html` 即可在浏览器打开。

## 覆盖范围

主流程闭环（对应 10 低保真原型屏 1 到 14）：项目列表 → 新建项目 → 新建建筑单元 → 照片上传打标（真实上传本机图片）→ 实测尺寸录入 → AI 识别 → 识别结果概览 → 人工校正 → 出图设置 → 图纸预览核验 → 负责人审核（可选门，退回即重开校正）→ 合规导出 → 交付记录。

**真实识别**：在设置页填入 Claude API key 后，识别环节把上传的照片直接发给 Claude 多模态模型（claude-sonnet-5），返回结构化部件表；提示词口径与 poc 盲测一致（受控类别词表、置信度、（估）标注、识别依据）。不填 key 或没有真实照片时退回模拟模式并明确标注。key 只存本机 localStorage。

内置两条示例数据，来自 poc 真实盲测结果：

- 高都玉皇庙主殿（13 部件识别结果，状态草稿，可完整走一遍闭环）
- 东呈古佛堂正殿（状态已出图 v1，演示重开校正与版本递增）

图纸预览用 poc 真实生成的 DXF 渲染图（assets/）。AI 识别用定时器模拟；新建单元的识别结果是通用占位并明确标注 demo 模拟。

## 代码结构与迭代方式

```
index.html          页面外壳，script 加载顺序：数据 → 状态 → 路由 → 界面
css/app.css         全部样式，灰白线框基调
js/data.js          全部模拟数据和受控词表。改数据、改下拉选项只动这个文件
js/store.js         状态读写 + 状态机（草稿→校正中→校正完成→已出图→重开校正）
                    状态流转只能走 transition()；校正动作走 correct() 自动记录
js/router.js        hash 路由 + UI 工具函数（表格、表单、徽章）
js/api.js           Claude API 调用（真实识别）、本机图片读取压缩、key 管理
js/views/*.js       一屏一个文件：
  projects.js       项目列表、新建项目、项目详情、新建建筑单元
  unit.js           建筑单元工作区（状态机可视化 + 五环节入口）
  input.js          照片上传打标（真实文件上传）、实测尺寸录入
  recognize.js      识别（真实 API 调用或模拟）、空照片/识别失败/空结果边界
  overview.js       识别结果概览（只读统计）+ 设置页（API key）
  parts.js          人工校正（可编辑部件表、校正记录、增量保护提示）
  review.js         负责人审核（通过/退回，退回自动重开校正）
  output.js         出图设置、图纸预览核验、送审入口、导出与交付记录
assets/             poc 真实图纸预览 PNG
```

加一个新界面的步骤：在 `js/views/` 新建文件，用 `Router.register("名字", fn)` 注册，在 `index.html` 末尾加一行 script。不需要改其他文件。

## 设计约定（与 07 PRD 对应）

- 状态机与版本：只有出图动作递增版本号，重开校正不清版本（R004/R005）
- 增量保护：重跑识别不覆盖已有校正（R003）
- 受控词表下拉 / 专名文字输入的区分与 10 原型一致
- 导出勾选中 JSON 标注为自留数据资产，非交付件（R006）
- 操作数据存 localStorage，顶栏"重置示例数据"可恢复初始状态

## demo 与真实产品的差距（如实声明）

- 识别已是真实链路（需自备 API key）
- 出图分两档：示例单元展示 poc 用 ezdxf 真实生成的 DXF 渲染图；新建单元由 `js/drawing.js` 从识别结果实时参数化生成 SVG 示意立面（画法库 v0，支持门窗墙/敞廊/三五开间/悬山歇山等构成），是示意级不是规范 DXF——规范图纸的参数化画法库是产品化下一步工程量（09 报告结论）
- 无登录、无多人协作、无后端，数据都在本机浏览器
- localStorage 容量约 5MB，照片压缩后一个单元建议不超过 8 张
