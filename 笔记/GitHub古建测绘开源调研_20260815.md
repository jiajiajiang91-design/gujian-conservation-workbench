# GitHub 古建测绘开源调研（2026-08-15）

> 检索方式：GitHub 仓库搜索 API，中英文关键词各两批（古建筑、古建 测绘、营造法式、斗拱、文物 数字化、古建筑 三维重建、ancient chinese architecture、HBIM、heritage BIM、scan-to-BIM、cultural heritage 3D reconstruction、dougong、HABS drawing），按 star 排序取前 8，另对 3 个已知项目做定点核验。检索日期 2026-08-15。
> 范围限制：未覆盖 Gitee（国内项目可能沉淀在 Gitee，见第 6 节验证清单）、GitLab 与高校自建仓库；中文多词查询存在无关高星仓库噪声，已人工剔除；star 数只反映关注度，不代表质量。

## 1. 总结论

在本次检索范围内，没有找到与"从测绘证据到正式成果交付"同定位的开源产品或成型原型。国际侧最接近的是 scan-to-BIM 研究代码集群（点云到建筑模型的自动化，研究性质）和遗产资产管理平台 Arches（管库存不管成果生产）；国内侧全部是零散的小型项目（计算工具、参数化库、展示原型、识别模型、课程作业），无一覆盖业务流程、专业责任与留痕。你的工作台定位（证据约束的成果生产链，含确认分级与全程留痕）在开源检索范围内是空白。

## 2. 国际侧发现

结论：国际开源力量集中在"点云怎么自动变成建筑模型"这一个技术环节，业务链条上下游（任务定义、证据管理、检查签发、交付）没有人做。

### 2.2 遗产管理平台

Arches（archesproject/arches，286 star，2026-08 活跃）：Getty 保护研究所背景的地理空间遗产资产管理平台，管的是"有哪些遗产、状态如何、在哪里"，不做测绘成果生产。它是开源遗产领域唯一称得上产品的项目，与本产品是上下游关系而非竞争关系（它管资产台账，你管单体成果生产）。

### 2.3 通用基础设施与技术热点

COLMAP（12482 star）与 CloudCompare（4661 star）是摄影测量和点云处理的通用底座，不含古建业务。2025 至 2026 年的热点是高斯溅射（Gaussian Splatting）用于文化遗产三维重建（韩国无人机加机器狗采集、实时渲染等多个小项目），特征是重建效果导向，同样不碰成果交付。HBIM 关键词下只有零散课程与试验项目，唯一值得记的是 chunibyo-wly/HBIM（港大 iLab，自动生成语义化 as-built BIM，2 star 研究代码）。

## 4. 与本产品的定位对照

结论：开源项目全部落在单点技术环节，本产品的差异化恰好在环节之间的链条上。

| 维度 | 开源现状 | 本产品 |
|---|---|---|
| 输入 | 点云、照片、古籍文本 | 任务书加照片加实测记录的混合证据 |
| 核心处理 | 单点：分割、识别、重建、计算 | 链条：识别、证据绑定、确认、生成、检查 |
| 输出 | 几何模型或展示页面 | 图纸、交付包、检查记录、来源说明 |
| 责任与留痕 | 无此概念 | 确认分级、签发权限、全程留痕 |
| 证据边界 | 无（模型直接输出结果） | 无证据不默认、推测必标注、降级可追溯 |

## 5. 对产品与求职的启示

1. 竞品表述口径：可以说"在 GitHub 检索范围内未见同定位开源产品"，不能说"没有竞品"。商业软件（如国内测绘院自用系统、点云厂商配套软件）不在本次范围内，属于 13 系列已有调研的口径。
2. scan-to-BIM 集群按 13-2 的框架用作能力上限参照：构件自动识别环节未来若要提升，BIMNet 的基准数据和竞赛代码是现成的评估起点。
3. 求职叙事新增一个可验证的点：本产品在开源生态中的空白定位，加上第 4 节对照表，是"市场判断"能力的直接证据。展示原型类项目（太和殿、佛光寺）可作为讲解古建构件层级时的公开参照素材。
