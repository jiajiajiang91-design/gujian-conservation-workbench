# 界面实现与 PRD 一致性核对

核对日期：2026-08-16。对照对象为 `05_界面与交互形态.md`（治理文档，界面结构与交互的唯一依据）与 `交互原型/02_AI工作台/设计资料/工作台视觉方案.md`（现行视觉方案）。

## 一、结论

发现四项偏离，其中一项属结构性，已修正；三项属视觉与信息层级，未修正，需 JIAJIA 定夺视觉基准后处理。

设计资料目录下存在两份互相冲突的视觉文档。`界面设计规范.md`（2026-08-07，Neubrutalism 风格，黄底黑框硬阴影、不用圆角）来自仓库基线提交；`工作台视觉方案.md`（2026-08-10）来自提交 8fa0f73 `feat(ui): rebuild tob workbench`，采用专业 SaaS 风格并声明参照 `integrations-page.zip` 的侧栏、搜索、卡片、灰白层级与紧凑控件。按时间与提交语义判断，后者取代前者。此判断需确认，确认后建议把前者标为历史失效。

## 二、已修正：中栏缺数据与证据双半区

`05` 第三节规定八种视图统一采用左侧数据、右侧证据结构，点击数据后证据区跳到对应位置并高亮；第 5.2 节的数据与证据双向联动以此为载体。

修正前，中栏为单栏，原始资料只有列表与下载按钮，照片、手写草图与图纸不能与数据并置核对。这同时使第 5.1 节框选加一句话缺少承载对象，是分发用例集中三条框选用例至今无法运行的原因。

修正内容（提交 9dfa8d6）：

- 资料、测量与尺寸依据、对象与构件三个视图引入证据半区，按 MIME 类型内联显示原件，图片与 PDF 直接渲染，其余类型给出下载提示，多份资料可切换。
- 任务进度按 `05` 图 1 从中栏移入左栏，状态按当前项目真实数据显示（资料份数、事实条数、对象数、待办数、是否已生成），不预设完成度。
- 中栏顶部改为视图标签，内容区数据宽度由 308 px 增至 462 px，证据区 379 px，1400 px 以下自动改为纵向堆叠。

验证方式为在团队演示项目上传测试图片后检查 DOM 布局与图像渲染，数据区与证据区确认为并置关系。
