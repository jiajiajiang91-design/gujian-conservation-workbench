# 界面实现与 PRD 一致性核对

核对日期：2026-08-16。对照对象为 `05_界面与交互形态.md`（治理文档，界面结构与交互的唯一依据）与 `交互原型/02_AI工作台/设计资料/工作台视觉方案.md`（现行视觉方案）。

## 一、结论

发现的偏离已全部处理：一项结构性偏离、三项视觉与信息层级偏离、两个缺失视图，均已修正。

设计资料目录下曾有两份互相冲突的视觉文档。`界面设计规范.md`（2026-08-07，Neubrutalism 风格，黄底黑框硬阴影、不用圆角）来自仓库基线提交；`工作台视觉方案.md`（2026-08-10）来自提交 8fa0f73 `feat(ui): rebuild tob workbench`，采用专业 SaaS 风格并声明参照 `integrations-page.zip` 的侧栏、搜索、卡片、灰白层级与紧凑控件。JIAJIA 于 2026-08-16 确认以后者为视觉基准，前者按历史版本处理。

## 二、已修正：中栏缺数据与证据双半区

`05` 第三节规定八种视图统一采用左侧数据、右侧证据结构，点击数据后证据区跳到对应位置并高亮；第 5.2 节的数据与证据双向联动以此为载体。

修正前，中栏为单栏，原始资料只有列表与下载按钮，照片、手写草图与图纸不能与数据并置核对。这同时使第 5.1 节框选加一句话缺少承载对象，是分发用例集中三条框选用例至今无法运行的原因。

修正内容（提交 9dfa8d6）：

- 资料、测量与尺寸依据、对象与构件三个视图引入证据半区，按 MIME 类型内联显示原件，图片与 PDF 直接渲染，其余类型给出下载提示，多份资料可切换。
- 任务进度按 `05` 图 1 从中栏移入左栏，状态按当前项目真实数据显示（资料份数、事实条数、对象数、待办数、是否已生成），不预设完成度。
- 中栏顶部改为视图标签，内容区数据宽度由 308 px 增至 462 px，证据区 379 px，1400 px 以下自动改为纵向堆叠。

验证方式为在团队演示项目上传测试图片后检查 DOM 布局与图像渲染，数据区与证据区确认为并置关系。

## 四、已补齐：两个缺失视图

`05` 表 2 列出的八种视图中，现状记录与图纸样式此前没有实现入口。

现状记录（提交 ca1bb0c）：域模型的 `Observation` 与 `Relation` 此前只能读取不能写入，新增 `CommitObservations` 命令。视图左半区列出空间关系、构造连接与已记录残损，右半区并置对应部位照片；人工录入必须选定一份项目资料作为依据，无证据引用的记录由域模型拒绝，已加测试覆盖。形制应然值与实测超容差的差异在本视图标为现状记录候选，与架构 v1.4 第 5.7 节一致。

图纸样式（提交 4026835）：图幅与视图配置此前只能在任务要求页以原始 JSON 文本查看与编辑。新视图把图纸标题、修订标记、图幅尺寸、视图比例、逐张图幅的视图数与逐个视图的图号图种比例以表格呈现，右半区显示已生成图纸的实际图面。构件画法与标注规则暂不提供选项，界面直接说明原因并指向差距清单，避免出现不影响成果的空选择。

## 五、核对为符合的项

- 三栏职责划分与 `05` 表 1 一致：左栏项目与进度、中栏当前对象、右栏对话与状态。
- 右栏三段结构与 `05` 表 3 一致：状态标识、消息流、输入区。
- 模型运行与费用视图符合 `05` 表 8 第 P16 项与 PRD R010，向用户显示服务状态与任务费用属明确要求，不是研发信息外泄。
- 助手动作与逐条确认机制符合 `05` 第八节。

## 六、剩余差异与后续

- 中栏顶部视图标签当前为 12 个，多于 `05` 图 1 线框示例的 5 个标签。`05` 表 2 定义八种视图，本实现另有三维模型、问题队列、模型运行与费用三项，均有 PRD 依据（R010 与第 P16 项原型页面），按覆盖而非偏离处理。
- 数据与证据的双向联动目前只做到选中资料即显示原件。`05` 第 5.2 节要求点击数据后证据区跳到对应位置并高亮，位置级联动依赖构件在照片上的位置框，属第 5.1 节框选修正的同一批能力，尚未实现。
- 构件画法与标注规则的可选项取决于图纸标注体系是否投入，见 `验证材料/15_图纸表达差距清单` 的方案 A 至 C。
