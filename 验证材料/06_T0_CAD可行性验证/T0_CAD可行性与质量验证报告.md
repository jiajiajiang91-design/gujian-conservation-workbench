# T0 CAD 可行性与质量验证报告

版本：v1.0<br>
日期：2026-08-11<br>
责任人：项目负责人

## 1. 结论

T0 通过，可进入 T1。

- T0-A 达到 L0：文件链路、对象映射、反向解析和外部软件打开通过。
- T0-B 达到 L1：古建局部专业样板、同源多视图、可编辑 CAD 和三维预览通过。
- 当前输出未达到 L2，不是用户参考图展示的完整成品。T10 和 T14 必须完成 L2，否则不得宣称专业成果可交付。

T0 通过表示技术路线可行，不表示完整产品、完整古建模型或正式图纸已完成。

## 3. T0-A 结果

T0-A 使用独立 `demo` 几何输入，生成 IFC、GLB、DXF、SVG 和 PDF。

- 30 个对象，对象 ID 和 IFC GUID 重复生成稳定。
- IFC 反向解析为 240 个顶点和 360 个面。
- DXF 包含 8 个原生尺寸和 43 条来源关系。
- 取消作业返回独立退出码，不保留部分输出或临时目录。
- AutoCAD 2024 审计为 0 错误；Blender 可导入和渲染 GLB。

这些结果只证明 IfcOpenShell 随附几何能力可用。T0 暂不增加独立 OpenCascade Python 绑定。

## 4. T0-B 结果

T0-B 使用团队自有的三开间 `demo` 参数化样板。

- 86 个语义模型对象，覆盖台基、基础、柱、梁、承托、檐、椽、屋面、瓦、脊、檐口、门和格扇窗。
- 南立面 465 个图元，横剖面 102 个，檐口详图 23 个，屋顶平面 74 个。
- DXF 包含 13 个原生尺寸、5 个填充、11 个图块引用和 104 条来源关系。
- GLB 中 86 个对象保留语义名称、类别和稳定 ID。
- 立面、剖面、详图、屋顶平面、DXF、SVG、PDF 和 GLB 来自同一参数版本。
- 样板包含一条明确标为 `demo` 的柱脚劣化记录，不伪装现场病害。

人工成组预览结论：可作为 L1 局部专业样板，不达到 L2。主要差距是完整平立剖矩阵、构件榫卯层级、斗拱和檐口节点深度、完整材料图例、保护做法、密集标高尺寸以及项目级图签索引。

用户提供的成品图纸和模型截图作为 L2 视觉深度参考，不复制到仓库。本轮不将无法核实来源的小红书内容写入标准依据。

## 5. 第二 CAD 工具

QCAD 3.32.9 试用版作为第二 CAD 验证工具，不进入产品依赖。

- 导入系统 DXF 后，脚本新增验证线并重算 13 个尺寸。
- 保存副本保留 13 个尺寸、5 个填充、11 个图块、104 条来源关系和 18 个中文标签。
- QCAD 生成的 A1 PDF 非空白，中文可读。
- 该副本由 AutoCAD 2024 再次打开和审计，结果为 0 错误、0 删除对象。

QCAD 保存时不写入 DXF 尺寸缓存图形，并增加 QCAD 辅助字体样式。QCAD 和 AutoCAD 能自动重建尺寸，但这个副本不能成为系统的规范成果。规范 DXF 始终由 worker 生成，外部软件保存的副本只作互操作证据。

LibreCAD 2.2.1.5 能打开 DXF 并生成 PDF，但中文被替换为占位符。该工具未通过，不进入支持矩阵。

## 6. 可复现性

- Python 3.12 / Windows x86-64。
- 16 个 wheel 已固定版本和 SHA-256。
- 全新虚拟环境在无网安装阶段使用 `--require-hashes`，安装通过。
- 7 项自动测试全部通过。
- 临时虚拟环境删除后不保留残留目录。
- SimHei 只从 Windows 系统读取，不重分发。部署前必须确认字体授权或替换为获得授权的中文工程字体。

## 7. 实施约束

1. T1 可开始，但 T0 样板不得放入宣传页或标记为完整产品成果。
2. T9 使用当前锁定的 IfcOpenShell、ezdxf、trimesh 和 ReportLab，本阶段不增加独立 OpenCascade 绑定。
3. T10 必须根据完整项目资料生成平面、四立面、纵横剖面、构造详图、完整三维模型和检查报告。
4. T14 必须用两套完整项目数据达到 L2，并由专业人员审查成组预览。
5. 任何缺失实测依据、责任身份或权限的项目仍然阻断正式签发。
